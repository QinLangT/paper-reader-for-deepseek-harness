# 论文问答

固定「怎么答」，不改「答什么」。装上之后，问论文里的某段话、某个式子、某个符号，回复的形状会变成：**先直答，再给预算，最后把深度交给你拉**。

## 它治的四个毛病

| 你遇到的 | 真实成因 | 插件里的结构约束 |
|---|---|---|
| 回复有很强的"防御性" | 不知道对错时最安全的写法就是处处限定 | **断言分三级**：论文原文直引 / 领域常识直说 / 推断写明"这是我的推断"。限定词只准出现在第三级；每条回答至少一个可判真假的断言 |
| 过于细致，完全看不懂 | 深度错配：讲了你没有的前置，或先给形式后给直觉 | **记号预算**：每个新记号在同段给读法 + 含义，一次最多 2 个；**分层顺序锁死**：直觉 → 形式 → 算例 → 边界 |
| 过于宽泛，没什么信息量 | 综述冲动（怕被指"漏了"） | **长度约束**：一句 ≤40 字可判真假的结论 → ≤4 句展开 → ≤3 项展开菜单。深度由你拉 |
| 切不中我问的问题 | 先从背景讲起，答的是相邻问题 | **第一句就是答案**：不许用背景铺垫开场，答案里必须出现你问题中的关键词；有歧义先说"我按 X 理解"再答 |

四条都写成**结构**（长度上限、必须出现的对象类型、限定词允许出现的位置、第一句的内容），没有一条是"要讲得通俗"这类形容词——形容词式提示没有可验证的产出。

## 怎么用

三档，从自动到手动：

1. **自动**：系统提示里常驻一段 347 字符（约 230 token）的约定，措辞限定在"你就论文或技术文本提问"时生效，所以写代码的对话基本不受影响。
2. **技能**：需要完整协议（分几层讲、被说"还是不懂"时怎么换、宽问题怎么收窄）时，模型会加载 `paper-answer` 技能；你也可以直接打 `/paper-answer` 强制走这套协议。
3. **口味档案**：说过一次"以后都先给结论""我不看推导"这类**长期**偏好，模型会覆盖写 `.dsh/paper-answer/style.md`，之后每次回答前先读它。当轮反馈不写档案，直接按换挡表改。

## 差评换挡表

说这些话时，协议要求换表征，而不是把同一段话再讲一遍：

| 你说 | 它做什么 |
|---|---|
| 太抽象 / 太虚 / 还是不懂 | 降一层具体度：给具体数字或最小例子 |
| 太深 / 太快 | 删推导，只留直觉 + 一个可检验的结论 |
| 太浅 / 太干 / 没感觉 | 加一个带失效边界的类比，或引论文原话 |
| 太长 | 压到 3 句，只留一个点 |
| 太保守 / 等于没说 | 去掉限定词，给一个可判真假的断言 + 一个预测 |
| 没回答我的问题 | 重读你原话，用你的词复述问题，只答那一句 |

同一处第二次被说"不懂"时，必须换一种表征并说明为什么换。

## 配置

在 `cordis.patch.yml` 的 `paper-answer` 行上改。没有导出 Config schema，字段由 `index.js` 自己校验——写错字段名会直接让该行不激活，而不是被静默忽略。

| 字段 | 默认 | 作用 |
|---|---|---|
| `pullMode` | `true` | 短答 + 展开菜单；`false` 时一次讲完（仍不超过 8 句） |
| `maxSentences` | `4` | 展开部分句数上限，1–8 |
| `stylePath` | `.dsh/paper-answer/style.md` | 口味档案路径（相对 workspace） |

## 边界（诚实清单）

- **这是提示词级别的约束，不是强制。** 它把"要不要讲深"从模型猜测变成结构约束，但模型仍可能不遵守；判断标准是实测：问一个宽问题看是否只给一句话主张 + 菜单，说"太抽象"看下一轮是否换表征。
- **它不提供论文原文。** 没有锚点的能力——那是 paper-reader 的 `paper open` / `paper locate` 要做的事。缺上下文导致的"答非所问"，这个插件治不了。
- **提示段是 profile 全局的。** 措辞用"当你就论文或技术文本提问时"限定作用域，但技术上它对所有会话可见，约占 230 token。
- **口味档案是覆盖写。** 只记当前状态，不记历史；要审计历史得靠会话本身。

## 协议覆盖

想改这份协议，在 workspace 里放 `.dsh/skills/paper-answer/SKILL.md`（带 YAML frontmatter）。项目层优先级高于插件运行时注册的同名技能，覆盖后无需改 profile 里的包。
